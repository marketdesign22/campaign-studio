# クライアント情報のAI自動取得

アカウント設定で公式ホームページ、Threads、Instagramのいずれかを入力すると、AIがクライアントプロフィールとトレンド検索キーワード候補を作成します。読み取り直後は `client_profile_drafts` に候補として保存され、利用者が承認するまで既存設定を変更しません。

## 情報源

- 公式サイト: 同一ホストの公開HTMLのみ。トップ、About、サービス、料金、事例、FAQ、アクセス、問い合わせ、ブログ/ニュースを優先します。
- Threads: 選択中アカウントの保存済みトークンと公式APIで、本人プロフィールと直近12投稿を取得します。入力URLは対象を指定するためだけに使い、スクレイピングしません。
- Instagram: 公式API連携前は、利用者が入力したプロフィールURLと紹介文のみ。ページ取得はしません。

## 取得上限とSSRF対策

- 1ページ 1.5 MB、最大8ページ、合計12万文字、1リクエスト8秒、リダイレクト3回
- `http` / `https` と標準ポートのみ。URL内認証情報は拒否
- localhost、ループバック、プライベート、リンクローカル、メタデータ、予約済みIPを拒否
- DNSの全候補IPを検査し、検査済みIPを通信に固定。リダイレクごとにURLとDNSを再検査
- 元URLと同一ホスト以外のリンク/リダイレクを拒否
- HTML/XHTML以外を拒否し、JavaScript、Cookie、ログイン、ダウンロードを使用しない
- `robots.txt` の `User-agent: *` / `Disallow` を尊重
- OpenAIキーやThreadsトークンを取得先サイトまたはAI入力へ送信しない

## 事実と推測

各項目は `verified` (確認済み)、`inferred` (推定)、`missing` (未取得)、`user_edited` (ユーザー修正済み) の状態、0〜1の信頼度、出典URL、ページ名、240文字以内の根拠を持ちます。AIが作った未知の出典URLは破棄し、出典の無い「確認済み」は「推定」へ下げます。情報源の不一致は `conflict` として表示します。

再読み取り時は現在値と候補値を並べます。`user_edited` の項目はAI候補で上書きされません。利用者が選んだ項目と有効にしたキーワードだけを承認済み設定へ反映します。

承認後は「AIで検索キーワードを改善」から、直近30日のキーワード別取得件数と除外件数を承認済みプロフィールと照合できます。AIは結果が少ない語を広げ、除外率が高い語を具体化した候補を作ります。この結果も新しい確認待ちドラフトになるため、承認前に検索設定を変更しません。

## AIとプロンプト安全性

AI応答は実行時スキーマで全25項目、キーワード、警告を検証し、不正な場合はDBへ保存しません。サイト/SNS本文は `UNTRUSTED_SOURCE_DATA` で区切り、文中の命令、Secret要求、外部URLへのアクセス要求に従わないよう指示します。実際の表現は複製せず、承認済みの事実と語調だけを原稿生成に渡します。

`OPENAI_API_KEY` が必要で、読み取りと原稿生成に選択モデルのAPI料金が発生します。読み取りはアカウントごと1時間に3回までです。

## DB

- `client_profile_drafts`: 確認待ち候補、入力元、警告
- `client_profiles`: アカウントごとの承認済みプロフィール
- `client_trend_keywords`: 分類、理由、顧客、地域、優先度、有効状態、出典、最終利用日、成果

すべて追加型で、`upgradeDb.ts` の存在確認付きヘルパーを使用します。ロールバック時は旧コードが新テーブルを参照しないため、テーブルを削除せずアプリだけを戻します。
