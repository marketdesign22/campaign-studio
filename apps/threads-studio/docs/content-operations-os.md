# コンテンツ運用OS

Threads Studioは、投稿作成とThreads Insightsに加えて、投稿後の問い合わせ・予約・購入などを記録し、その結果を次の週間計画へ戻せます。データは常に選択中のThreadsアカウントで分離され、戦略や修正案が自動公開されることはありません。

## コンバージョン計測

「分析」画面ではアカウント別に成果目標を作成し、7日・30日・任意期間のクリック、CTR、成果数、CVR、成果金額を確認できます。投稿・キャンペーン・目標別の内訳と、トレンド使用/未使用、AI生成/手動作成の比較も表示します。イベントが5件未満なら参考値と表示し、分母が0または未取得なら率は `—` とします。実測0件とは区別されます。

成果は手動登録、CSV、署名付きWebhookから入力できます。氏名、メールアドレス、IPアドレス、Cookieを標準項目として収集しません。`externalEventId` はアカウント内で一意で、再送を重複計上しません。手動イベントの修正前データは `conversion_event_revisions` に残ります。

### UTM

通常の `http` / `https` URLへ `utm_source`、`utm_medium`、`utm_campaign`、`utm_content`、`utm_term` を追加します。既存クエリとフラグメントは維持し、既存UTMは新しい値へ置換します。認証情報入りURL、非HTTP URL、4,096文字を超える生成結果は拒否します。外部短縮URLサービスやリダイレクト機能は使用しません。

### Webhook

受信先は `POST /api/conversions/webhook/:accountId`、`Content-Type` は `application/json` です。本文上限は128KB、アカウントごとに1分120件までです。必須ヘッダー:

- `x-webhook-timestamp`: Unix秒。サーバー時刻との差が5分以内
- `x-webhook-signature`: `sha256=<hex>`

署名対象は `${timestamp}.${accountId}.${rawBody}`、方式は `HMAC-SHA256`、鍵は `CONVERSION_WEBHOOK_SECRET` です。これによりURL上の `accountId` 改ざんも検出します。同一署名の再利用、未知のフィールド、不正JSON、他アカウントのpost/goal IDは拒否します。Secretや受信本文はログへ出しません。

### CSV

UTF-8 CSVの必須列は `eventType,eventTime,quantity`。任意列は `postId,conversionGoalId,valueCents,currency,externalEventId,campaign,note` です。最大256KB・1,000行。列値の数式形式は拒否し、メモの先頭が `= + - @` の場合はExcel等で実行されないよう無害化します。インポート前後ともアカウント所有権を検証します。

将来のGA4、CRM、独自フォームは、共通の成果イベント形式へ正規化するアダプターとして追加します。現在は認証情報のない外部サービスへ通信しません。

## 7日間のコンテンツ戦略

サイドバーの「コンテンツ戦略」から、開始日と任意の目標を指定します。AIへ渡すのは選択中アカウントの承認済みプロフィール、予約、直近実績、トレンド、投稿枠、目的比率だけです。返答は実行時スキーマで検証し、7日分でない、テーマが5種類未満、販売/問い合わせが4件以上、指定日と不一致の結果は保存しません。

各カードは目的、テーマ、フック、CTA、形式、推奨時刻、トレンド、理由、期待成果、信頼度、仮説、要事実確認を持ちます。編集・除外・再生成ができ、カードから500文字以内の異なる3案を作れます。選んだ案だけを既存承認フローの原稿としてカレンダーへ追加します。

設定で自動週間戦略をONにすると、日次メンテナンス時に当日を含む戦略がない場合だけ下書き戦略を作ります。週間振り返りをONにすると開始7日後に一度だけ振り返りを作ります。AI未設定/失敗時は既存戦略、原稿、設定を変更せず、投稿処理も止めません。振り返りは対象7日間の投稿だけを使い、少数サンプルでは警告を必須にします。

## 成果連動型の過去投稿参照

AI原稿生成は最大8件を重複なしで選びます。最近の文体3件、エンゲージメント率・クリック・成果・鮮度を含む成果上位3件、テーマ類似2件です。データ不足時は存在する最近の投稿へ安全にフォールバックし、1年以上前の投稿は除外します。

## 投稿前品質チェック

編集画面の「AI品質チェック」は項目別に問題なし、改善推奨、要確認、投稿停止を表示し、理由、根拠、重要度、修正案、自動修正可否、人間確認要否を返します。AIにはブランドの語調、地域/言語、承認済みサービスと同一アカウントの最近の投稿だけを渡します。外部文章は区切られた非信頼データとして扱います。不正なJSONは保存しません。

「安全に修正案を作る」は元原稿を維持して前後と変更理由を表示し、利用者が明示的に反映します。500文字を超える案、数字・URL・ハッシュタグ等を変える案は拒否します。

投稿、承認、予約、自動投稿の直前にはAIを使わない決定的検査を実行します。停止条件は空本文、500文字超、アカウントの禁止語、Secretらしい文字列、メールアドレス、不正/非HTTP URLです。AIだけの曖昧な判定は必ず「要確認」以下へ下げ、投稿停止には使いません。既存の必須承認とアカウント所有権検査もそのまま適用されます。

## DB変更

追加テーブルは `campaigns`、`conversion_goals`、`conversion_events`、`conversion_event_revisions`、`content_strategies`、`content_strategy_items`、`weekly_reviews`、`post_quality_checks`、`post_quality_findings`。`posts` にはキャンペーン、戦略項目、成果目標、追跡メタデータ、作成経路、品質状態を追加し、`account_settings` には週間数、目的比率、CTA、禁止テーマ、品質強度、AI上限、自動戦略、振り返り、成果計測の設定を追加します。

`pnpm db:upgrade` は `information_schema` で存在確認してから追加するため再実行可能です。既存列の削除や既存値の書き換えはありません。金額は通貨最小単位の整数 `valueCents`（MySQL `bigint`）です。時刻はDBでUTC、戦略日はアカウントのローカル日付 `YYYY-MM-DD` です。

## 環境変数とデプロイ

既存の `OPENAI_API_KEY` / `OPENAI_MODEL` をAI機能に使用します。Webhookを使う場合だけ、十分に長いランダム値を `CONVERSION_WEBHOOK_SECRET` に設定します。実値はGit、画面、ログへ出さないでください。

デプロイ前にDBバックアップと `pnpm db:counts` の結果を保存し、`pnpm check && pnpm test && pnpm build` を実行します。Render/Railwayのpre-deployで `pnpm db:upgrade`、その後 `pnpm start` を実行します。Render無料構成は `/api/scheduled/tick` が日次メンテナンスも起動します。

ロールバックは直前アプリ版へ戻します。DB変更は追加型なので旧版は新テーブル/列を無視して動作します。新データを保持するため、通常はテーブルや列を削除しません。完全削除が必要な場合だけ、バックアップ後に別途レビュー済みSQLを用意してください。

## 既知の制限

- Threads APIだけでは外部サイトのクリックや問い合わせを自動取得できないため、Webhook/CSV/手動入力が必要です。
- GA4/CRMアダプターと独自短縮リンクは将来対応です。
- AI戦略とAI品質チェックにはOpenAI設定が必要です。決定的な投稿前検査は設定なしでも動きます。
- 比較は因果関係を証明するものではなく、イベント数が少ない期間は参考値です。
