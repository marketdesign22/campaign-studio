# 月次クライアントレポート

## 使い方

`/report` で対象月を選び、クライアント名・作成者名・運用目的・月次目標・特記事項を保存します。目標は空欄でも使えます。「取得済みデータから新しい版を生成」で実績を固定し、文章を作成します。先に分析画面で実績を取得すると、次に生成する版に反映されます。

既存の `OPENAI_API_KEY` / `OPENAI_MODEL` をそのまま使用します。キーがない場合、API障害、出力検証の失敗時は、計算済みデータに基づく標準文の下書きが保存されます。AIには集計済み指標、カテゴリ別集計、上位投稿の短い本文、運用目的、特記事項だけを渡し、トークンや問い合わせの個人情報は渡しません。

文章を編集・保存し、確認後にレビュー済みにします。レビュー後は内容を固定し、修正する場合は複製して新しい下書きを作ります。PDF保存は既存のブラウザ印刷を利用します。A4を選び、ブラウザのURL等のヘッダー・フッターはオフにすることを推奨します。「送付済み」は記録操作であり、メール送信を実行しません。

「月初に前月の下書きを自動作成」を設定すると、既存の日次メンテナンスで前月分を作成します。処理は一意キーで重複を防ぎ、月初の実行を逃した場合も後日作成できます。クライアント名・目的は次月に引き継ぎますが、目標値、施策メモ、成果登録完了の確認は月ごとに設定します。自動生成の通知はサーバーログのみです。

## 集計の契約

- アカウントの主タイムゾーンで公開月と投稿日時を統一。夏時間の月も月初・翌月初のUTCオフセットを個別計算。
- インサイトは公開月ごとの投稿累計。月内に発生したアカウント全体の閲覧数ではありません。アプリの公開履歴外の投稿は対象外です。
- ERは `(likes + replies + reposts) / views * 100`。欠損・分母ゼロはnull。期間ERは反応合計をビュー合計で割ります。
- 前月は生成時点の前月公開投稿の累計値です。投稿の経過日数が異なるため参考比較と注記。途中月は前月増減を出しません。
- フォロワー純増には前月末と当月末（速報なら当日）の正確な日付の記録が必要です。近隣の記録を月末値とみなしません。
- 成果は `inquiry / booking / lead / purchase / custom` を対象とし、フォローやプロフィール訪問を事業成果に加算しません。成果種別・キャンペーン別に内訳を掲載。登録完了未確認の期間は、件数を部分実績として扱い、達成率を表示しません。複数の成果行動を合計しており、ユニーク顧客数ではありません。
- TOP/BOTTOMは50ビュー以上の投稿のER順。掲載は重複なし。50は比較の目安であり統計的有意性を保証しません。
- 日次投稿記録は生涯累計カウンタ。各観測日の対象投稿数と合わせて表示し、「日別閲覧数」と誤表示しません。
- AI自由文は数値を出力しない形式とし、数値は集計済みの表で提示。根拠参照と形式を検証してから保存。意味の妥当性・因果関係は担当者がレビューします。

## データとデプロイ

新規テーブルは `report_post_daily`、`report_configs`、`monthly_reports`。既存の `pnpm db:upgrade` に追加済みです。既存データを削除・上書き移行しません。Render設定の起動コマンドがこのコマンドを実行します。日次取得の対象を直近90日の公開投稿へ拡張し、429を検出したアカウントはその回の残りをスキップします。投稿インサイトのリクエストは15秒でタイムアウトします。

生成したレポートは数値・定義・文章・対象アカウント・期間・取得日時を保存します。編集と状態変更はアカウント条件と改訂番号で保護し、他アカウント参照や同時編集による上書きを防ぎます。

公開前に、実際のDBを用いたアップグレードの再実行、生成・編集・レビュー・PDF保存、アカウント切替をステージングで確認してください。自動生成は画面設定が有効な場合に限り動作します。

## 今回の接続範囲と残る追加連携

- 投稿4指標、フォロワー履歴、カテゴリ・キャンペーン・投稿目的、既存の成果登録を接続。
- quotes / shares / アカウントviews・clicks / 属性データは新規取得していません。公式仕様と対象アカウントでの取得可否を確認してから追加します。現行のER定義を黙って変えません。
- 地域・言語タグの入力機能は未追加です。本文から推測した属性をレポートに使いません。
- GA4のLPセッション、クリックと成果の同一対象への帰属は未接続。CTR・CVRを、範囲が異なる数値で割って表示しません。
- PDFはブラウザ保存。サーバー側Puppeteer、PDFファイルURLの保存、共有URL、ロゴアップロード、オーナーメール通知は未追加です。
- 過去の日次記録を創作して補いません。日次履歴はこの変更の公開後から蓄積します。

## 検証

月境界・夏時間、ERの重み付け、欠損、前月ゼロ、途中月、月末の基準値不足、事業成果の分類、順位の重複、AIの数値創作・不正根拠、レビュー後の編集禁止、改訂競合を自動テストで確認。既存のDBアップグレードテストで再実行時の冪等性を確認します。

実環境のDB・Threads・AIサービスへの接続と、ブラウザで保存したPDFの全ページ確認は公開前の確認事項です。
