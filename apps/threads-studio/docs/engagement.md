# エンゲージメント（他アカウントの投稿へのコメント）

トレンド機能で収集した他アカウントの公開投稿へ、こちらから公開コメントを送る機能です。「受信箱」が自社投稿についた返信への対応なのに対し、こちらは能動的にコメントしにいく側です。

## 構成

| 層 | ファイル | 役割 |
|---|---|---|
| 送信・返信取得 | `server/engagement.ts` | 対象投稿についた返信の一覧取得、コメントの送信 |
| API | `server/routers/engagement.ts` | 対象の返信一覧 / AI下書き / 送信 / 送信済み件数 / 履歴 |
| 共通ロジック | `server/threadsErrors.ts`, `server/threadsApi.ts` | Threads APIのエラー分類、`publishReply`（返信管理と共有） |
| 画面 | `client/src/pages/Trends.tsx` `EngagementBox` | トレンドの投稿カードに埋め込み。対象選択・AI下書き・送信 |

## 対象の選び方

コメント先はトレンド機能で**このアカウントが収集済みの投稿**からだけ選べます。任意のURLを貼って知らない投稿へコメントする経路は用意していません（収集していない投稿の内容をAIが正しく踏まえられないため）。

投稿本体だけでなく、その投稿についた返信（他人のコメント）へ返信することもできます。ただし他アカウントの投稿の返信一覧は、Threads側の権限モデルにより取得できない場合があります。その場合は例外を投げずに `available: false` を返し、画面側は「投稿本体へのコメント」にフォールバックします（`server/engagement.ts` の `listPostReplies`）。

## Threads API

- 対象投稿の返信一覧: `GET /{threads-media-id}/replies`（自社投稿を取得する `fetchAccountReplies` とは別のエンドポイント。任意のメディアIDを渡せる `fetchPostReplies`）。必要権限: `threads_read_replies`
- 送信: 通常投稿・受信箱の返信と同じ2段階（コンテナ作成→公開）に `reply_to_id` を足すだけ（`threads_manage_replies`）。`reply_to_id` には投稿本体のメディアID、または返信のメディアIDのどちらも渡せる
- 投稿本体のメディアIDはサーバー側でトレンド投稿の行から解決し、クライアントへは渡さない（画面が持つのは内部の行IDだけ）。返信を対象にする場合は、直前に取得した返信一覧のIDをそのまま使う

## AI下書き

AIが作るのはコメント案を1件だけ。対象投稿の要約（トレンド機能が保持する140文字程度の要約。全文ではない）、または対象の返信本文と、このアカウントの過去投稿の文体を渡して短い返信文を作らせます。宣伝・売り込みにしない、80文字程度の会話として自然な長さにする、という指示を入れています。

**自動では絶対に送信しません。** 案はその場に表示されるだけで、実際にThreadsへ送るのは利用者が内容を確認し「送信」を押した時だけです。1分あたりの下書き生成回数、送信の連打防止（3秒間隔）も他のAI機能・返信管理と同じ考え方で掛けています。

## データ

追加型・冪等（`server/scripts/upgradeDb.ts`）。既存テーブル・列は変更しません。

- `engagement_comments`: 送信したコメントの記録。監査用途で、全文の複製ではなく短い要約（`targetSummary`、最大255文字）だけを持つ。対象が削除されても記録は残す

## 安全策

- APIキー・アクセストークンはクライアントへ返さない
- 対象はこのアカウントが収集済みのトレンド投稿に限る（他アカウントの投稿を無断で選べない設計）
- 送信は1回だけ。AIによる自動送信は無い
- 送信は3秒間隔で連打を防止。AI下書きは1分あたり10回まで
- 失敗はThreadsのエラーを種別（認証・権限・レート制限・通信）に分類し、日本語で「次に何をすればよいか」を案内する
- ログにはトークン・投稿本文・APIの生レスポンスを出さず、失敗の種別だけ残す

## 制限事項・今後

- 対象は収集済みのトレンド投稿に限る（任意URLからのコメントは非対応）
- 他アカウントの投稿の返信一覧はThreads側の権限次第で取得できないことがある（取得できなければ投稿本体へのコメントに切り替える）
- 同じ対象への重複コメントはブロックしない（`engagement.countForTarget` で目安件数を確認できるのみ）
